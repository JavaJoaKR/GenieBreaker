# GenieBreaker

KT GenieTV MA4000 / MARUSYS, Android 14를 위한 TV 블루투스 앱입니다.
다크 네이비·민트 UI, 큰 선택 영역과 방향키 포커스를 제공합니다.

## 첫 버전

- 주변 Bluetooth Classic 기기 검색·검색 중지
- 등록된 기기 및 주변 기기 표시, 중복 제거
- 앱 내 페어링 요청 및 상태 갱신 (최종 PIN·동의는 Android 보안 확인 창)
- 근처 기기 권한 요청과 Bluetooth 켜기 요청
- 기본 설정 앱으로 이동하지 않음
- ADB·루트·Shizuku 불필요

페어링은 실제 연결과 다릅니다. 등록된 기기의 연결·해제·등록 삭제는 펌웨어 호환 API를 통해 시도합니다. API가 없거나 시스템 권한 검사가 거절하면 실패 원인을 표시하며, 일반 앱 권한으로 강제 우회하지 않습니다. BLE 전용 검색은 아직 지원하지 않습니다.
제조사 펌웨어가 시스템 페어링 확인 창이나 켜기 요청을 차단하면 해당 동작은 실패할 수 있습니다.
Shizuku 권한 확장은 후속 범위입니다. 아직 MA4000 실기기에서 검증하지 않았습니다.

## APK

[Releases](https://github.com/JavaJoaKR/GenieBreaker/releases)에서 최신 개발 빌드 APK를 받으세요.
모든 브랜치 push마다 빌드·Lint 후 커밋별 prerelease와 APK·SHA256 체크섬을 발행합니다.
PR은 검증과 artifact 업로드만 수행합니다. 여러 커밋을 한 번에 push하면 해당 push의 최종 커밋을 빌드합니다.
Kotlin 코드와 Android 기본 UI만 사용하므로 ARM32(armeabi-v7a)에 네이티브 라이브러리 제약이 없습니다.

## 개발

JDK 17, Gradle 8.11.1, Android SDK 35 / Build Tools 35.0.0.
Gradle wrapper는 아직 포함하지 않으며 위 버전의 설치된 Gradle로 빌드합니다.

```sh
base64 --decode development-keystore.base64 > release.jks
gradle :app:assembleRelease :app:lintRelease
```

`development-keystore.base64`는 **공개 개발용 서명 키**이며 비밀이 아닙니다.
동일 키로 개발 빌드 간 업데이트를 지원합니다. 신뢰할 수 있는 공식 배포용 키로 사용하지 마세요.
정식 배포 전 별도 비공개 키와 CI Secrets로 전환해야 하며, 키 전환 시 기존 개발 APK를 삭제 후 재설치해야 합니다.

## 기기 확인

1. APK 설치 후 TV 런처에서 GenieBreaker 실행.
2. ‘권한 허용’으로 근처 기기 권한 승인.
3. Bluetooth가 꺼져 있으면 ‘블루투스 켜기’ 선택.
4. 헤드폰·키보드 등을 페어링 모드로 두고 검색.
5. 기기 선택 후 Android 페어링 확인 창 승인.
6. 등록 목록 갱신, 검색 중지, 뒤로 가기, 재실행, 권한 거절 후 복구 확인.

## 앱 내 업데이트

앱 시작 시 6시간 간격으로 GitHub의 main 채널 릴리즈를 확인하고 새 APK를 자동 다운로드합니다. 왼쪽의 업데이트 버튼으로 수동 확인 및 설치할 수 있습니다. 이 기능이 포함되기 전 버전에서는 최초 한 번 새 APK를 직접 설치해야 합니다.

업데이트는 같은 앱 ID, 더 높은 versionCode, 같은 서명 인증서가 모두 일치해야 설치를 요청합니다. GitHub main 채널의 개발용 prerelease도 대상으로 합니다. APK 파일은 앱 전용 캐시에 보관하고 설치 프로그램에만 읽기 URI를 전달합니다. Android의 ‘알 수 없는 앱 설치’ 최초 허용과 설치 확인이 필요하며, 무인 설치는 지원하지 않습니다. 펌웨어에서 설치 화면을 막았다면 자동으로 우회하지 않습니다.

## 이름 갱신과 화면 검사

`ACTION_NAME_CHANGED`로 뒤늦게 도착한 기기 이름을 반영합니다. 주소별 이름을 유지하고 기존 행의 텍스트만 갱신하여 포커스와 스크롤을 유지합니다. 이름 모델 단위 테스트와 Android 에뮬레이터의 방향키 포커스·스크린샷 검사를 실행합니다.

## 페어링과 호환 제어

기기를 선택하면 앱 내부 메뉴를 표시합니다. 새 기기는 일반 페어링 또는 Android CompanionDeviceManager의 대체 페어링을 선택할 수 있습니다. 대체 방식은 해당 펌웨어가 서비스를 제공할 때만 사용할 수 있으며 시스템의 기기 동의 창이 표시됩니다. 기본 블루투스 설정 앱으로 보내지 않습니다.

등록된 기기는 A2DP 또는 HID 프로필의 연결·해제 및 등록 삭제를 요청할 수 있습니다. 비공개 호환 메서드는 제조사·Android 정책에 따라 없거나 차단될 수 있습니다. 리플렉션은 시스템 권한을 부여하지 않으며, 실패하면 이유를 표시합니다. 요청이 수락된 것과 실제 연결 완료를 구분합니다. 링크 연결 여부는 앱 실행 중 수신한 ACL 이벤트에 기반하며 오디오 출력 여부를 의미하지 않습니다.

페어링의 시스템 호출은 작업 스레드로 분리했습니다. 예외는 UI에서 처리하고 '오류 기록'에 남깁니다. 프로세스의 미처리 예외도 다음 실행 시 확인할 수 있습니다. 기록은 앱 내부에 저장하며 사용자가 복사하기 전에는 외부로 전송하지 않습니다. 실제 MA4000 종료 현상의 원인은 로그 없이 확정하지 않았습니다.

## 앱 실행과 표시 이름

'앱 실행 / 이름'에서 설치된 런처 앱을 선택해 직접 실행하거나 GenieBreaker 내부 표시 이름을 저장할 수 있습니다. 통신사 런처만 실행을 막는 경우 직접 실행을 시험할 수 있지만, Android 정책·앱 자체 검사·DRM 차단을 해제하는 기능은 아닙니다. 설치된 APK의 패키지명·서명·다른 런처의 앱 이름은 바꾸지 않습니다.

## 검증 한계

CI에서 이름 갱신 단위 테스트, APK 빌드와 Lint, 에뮬레이터의 포커스 유지 및 업데이트 파일 제공자의 경로·쓰기 차단 검사를 실행합니다. 에뮬레이터는 MA4000 블루투스 하드웨어나 KT 정책을 재현하지 않으므로 페어링·연결·대체 페어링·업데이트 설치의 실기기 검증이 별도로 필요합니다.
